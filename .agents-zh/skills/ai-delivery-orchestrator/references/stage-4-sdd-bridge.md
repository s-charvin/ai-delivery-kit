# Stage 4：实现桥接

把 `implement` 映射为有边界的执行与 `.ai-delivery` 进度证据。

## 何时执行

当 reconcile 为依赖就绪的 `design_ready` 或 `in_dev` 切片输出
`NEXT_ACTION=implement` 时执行。当前 hash 绑定设计评审即为批准范围内的
开发授权，不存在第二个开发 checkpoint。

`figma` / `runtime-baseline` 复用 Stage 2 的准确 workspace；其他模式默认
使用当前 checkout。

## 从设计契约形成执行 brief

| 来源 | 执行用途 |
|------|----------|
| `design.md` 范围与 `B-###` | 行为边界和当前目标 |
| `AC-###` 与追踪 | TDD 与验收条件 |
| 依赖图和项目架构 | 安全顺序和编辑所有权 |
| 当前代码与测试 | 具体文件和验证命令 |
| UI truth scenario | 视觉、交互、动效、资源与运行时证据 |
| 可选 `progress.md` | 已完成、待完成、阻塞和最近验证结果 |

brief 是临时执行上下文，不是新治理产物。不得持久化 `spec.md`、`plan.md`
或 `tasks.md`，也不得把文件级步骤复制进 `design.md`。

每个最小执行单元都必须经过 TDD 和新鲜上下文评审。可复用问题先更新
`retrospective.md` 并报告 `RET-###`。

<a id="ownership-preserving-execution-brief"></a>
## 保持既有所有权的执行 brief

修改已有代码时，先读取适用的仓库规范并追踪真实调用链，再选择任务边界与
测试形式。父 agent 的 brief 包含以下四项简短信息；引用原文位置，不复制整份规范：

| 条目 | 必需内容 |
|------|----------|
| 约束 | 适用的仓库规范路径及本单元必须保留的具体规则，区分来源要求与实现建议。 |
| 既有权威 | 具体状态/资源 owner、进入与终态转换，以及应复用的现有守卫。所有权未知时先调查，再分派编辑。 |
| 修改边界 | 可观察变化、编辑范围、共享依赖，以及新增抽象、状态或权威的必要性依据。 |
| 验证 | 先明确所需行为与禁止副作用，再选择适用的最低既有测试层，并提供共享边界的集成证据。 |

需求、文档、任务分工和文件编辑权属于跟踪或执行边界，不自动形成独立的生产
owner。共享生命周期、可变权威或终态守卫的改动交给同一实现者，或围绕同一
owner 顺序执行。文件不同不足以证明独立；只读调查可以并行。

实现者必须自行读取适用仓库规范并核对 brief。父任务书和框架偏好都不能豁免
用户或仓库约束。在已授权范围内纠正技术任务划分并告知父 agent；需要用户
决定的冲突应在依赖编辑前提出。

确认生产所有权后再选择测试。独立或纯逻辑测试用于真正存在的逻辑，不能因为
任务书要求这种测试，就仅为易测而抽取生产生命周期。标识与时间可以作为附加
上下文，不必成为就绪、完成、有效性或去重的第二个权威。新增生命周期状态或
权威必须对应现有 owner 尚未表达或推导的独立事实；保留既有权威的无状态抽取
可以基于复用、清晰度或真实依赖边界成立，单独的任务或易测性不足以作为依据。
适用的宿主测试较慢时仍应使用，或
记录真实验证缺口，不能为了满足任务书而改变架构。

返回摘要说明复用的守卫，并解释新增状态或抽象；最终集成评审沿合并后的调用链
复核，不能只接受各单元测试通过。信息放在临时 brief 与既有评审记录中，不新增
治理产物或审批门禁。

## 可选进度记录

仅在需要跨会话恢复时使用需求级 `progress.md`，简洁记录：

- 已完成工作及关联行为/验收 ID；
- 待完成工作；
- blocker 及范围；
- 验证命令、结果与评审结论。

它不是第二份计划，也不能提升 gate。

## 评审与验收

执行闭环：实现 → 新鲜上下文评审 → 修复 → 重新评审，直到 clean 或预算
耗尽。随后做完整切片评审、必要的视觉/动效验收和最终验证。

启用 UI truth 时，schema v2 `visual-acceptance.json` 必须绑定当前 v3 index，
并且每个索引 scenario 恰好有一条结果：

- `component-only` 使用冻结的真实组件预览和适用行为证据，不声称宿主组合；
- `host-static` / `host-runtime` 使用 hash 绑定 runtime capture、生产测试、
  几何/landmark 断言、命令、评审者和 host provenance；
- 每个 unit 独立验收动效；静态 golden 不能替代动效验收。

运行时截图保存在 `.ai-delivery/` 外、index 指定的项目原生证据根。waiver
必须含用户身份、时间和原因。

```text
design_ready → in_dev → [visual_acceptance_passed] → merged
```

`none` / `existing` 跳过 `visual_acceptance_passed`。
