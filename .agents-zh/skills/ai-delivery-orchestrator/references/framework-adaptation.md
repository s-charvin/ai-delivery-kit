# 框架适配

编排器拥有状态、gate、blocker、handoff 和持久化产物形态。已安装框架只
贡献推理方法或执行纪律，不新增阶段和必需文档。

## 产物边界协议（必须）

- 正式流程产物使用 `.ai-delivery/meta/project-binding.json` 解析出的canonical路径；辅助材料按下文放所属需求内，无需逐种增加绑定。Stage 3唯一契约仍是 `design.md`，可选恢复使用 `progress.md`。
- 宿主树只允许写生产源码、项目原生测试、golden/官方预览和运行时资源。
- 调用外部 skill、命令、agent 或 hook 前，传入准确 canonical 输出映射和
  已批准 workspace。`docs/superpowers/**`、`.superpowers/**`、`.specify/**`
  与 `openspec/**` 默认路径全部禁用。
- 若步骤无法遵守映射，不调用该持久化步骤；在会话内应用方法并直接写
  canonical 产物。禁止先在其他位置生成再搬运。
- 在完整批次入口/出口及推进门禁前，比较 Git 状态/内容与每个外部默认输出根的独立文件系统指纹，包括 ignored 文件、类型、symlink target 与 SHA-256。仅当能覆盖批次中所有写入方及输出根时，才合并受控调用的审计；期间持续限制输出映射。未知写入方、输出根变化或覆盖不明时单独完整审计，不仅凭 mtime 或 tracked 路径复用。越界写入设置 `blocked_verification_failure`，不得删除或改写用户既有文件。

## 轻量产物组织

正式路径继续通过 `project-binding.json` 与 `layout.py` 解析。允许在所属需求内保存辅助材料，不为每种文件加入绑定。这些约定约束后续创建，不增加目录校验、文件数上限、manifest、命名门禁或强制整理阶段。

创建前先判用途、所属对象、现有承载位置和发现入口。能更新已有正文就原位维护；只有独立来源、审查范围、运行或需保全的尝试才拆文件。小需求不创建空目录或额外报告。

| 材料职责 | 维护方式与边界 |
|---|---|
| 复盘、设计合同、当前解释／人工清单 | 在各自唯一正文持续整合；原始需求另留。不得另建补充复盘／设计补丁或竞争的最新清单。 |
| 状态与进度 | `status.json` 负责状态；进度为简短当前摘要和链接，不重复粘贴日志或另造状态表。 |
| 用户原文、决定、评审与验证轮次 | 在各自记录保留真实顺序及替代关系。`verification.md` 可以按轮次追加，不等于补丁式复盘；同轮结论不复制成多份摘要。 |
| 日志、截图、profile、来源导出、冻结证据 | 保留来源版本／独立运行身份及失败原件。不覆盖旧失败、不合并独立运行、不更改原件沿用旧确认、不以新运行冒充旧证据。 |
| 调研、覆盖／数值分析、Mock、diff、保全快照 | 有具体问题、来源、范围或复现用途才生成；主题结论原位维护，必要原始观察按次留存。不凑空报告、不无新信息反复导出、不复制整棵历史目录。 |
| AI交接与人工交付材料 | 有实际交接／阅读用途才生成，引用权威需求、状态、设计及证据。不每轮自动生成作者说明、同义结果摘要、平行有效需求或完成状态。 |

既有禁止边界保留：不得生成与 `design.md` 竞争的 `spec.md`／`plan.md`／`tasks.md`，不得向外部框架默认目录写治理产物，不得用平行 `ui-contract.html` 代替宿主UI，不复制归档快照。禁止针对用途，不是全仓按名字禁用：原生manifest、测试夹具、用户附件及只读历史仍按职责保留。禁止冗余副本不允许删减问题、用户原文或必要失败证据；已有原件不能借规范化删除。

### 默认按用途归属

优先沿用已有等价目录；单子需求就近存放，横跨子需求只保一份需求级正文，其他地方引用。以下是默认建议，不是必建目录树或schema。

| 用途 | 默认归属及发现入口 |
|---|---|
| 用户原文 | 需求 `prompts/`，每个独立任务一组顺序输入，见下文。 |
| SDK／API／平台／迁移调研 | 大量材料可用 `research/<topic>/`；小需求只有一份明确命名报告时可沿原位置。 |
| Figma结构、导出及源素材 | 已有 `design-evidence/<topic>/`；来源快照不是生产实现。 |
| Mock及测试数据 | 已有原生夹具或 `self-test-mocks/`。 |
| 详细审查、诊断、差量及必要失败保全 | 已有 `reviews/<topic-or-batch>/` 或等价目录；简单发现直接进入 `verification.md`，独立阅读确有价值才拆出，并从正式入口引用。 |
| 日志、截图、设备结构、profile、官方预览 | 项目原生报告和索引指定证据根；保留UI真值路径／哈希与宿主验收规则，不大批复制到 `.ai-delivery`。 |
| 人工清单和AI续接／交接提示词 | 更新已有人工入口；材料多时可用 `handoff/`。用户实际发来的续接仍完整进入 `prompts/`。 |

`contracts/` 只放现有合同及其索引材料，不收所有草稿和诊断。相同来源内容未变时尽量引用已有导出；独立运行即使字节相同也保留身份。优先链接原运行／快照，只有会被工具覆盖或需离线保全时，才复制必要部分并说明来源。不另造全局素材库、内容寻址、哈希清单或去重服务。临时计算／转换中间数据可按宿主规则使用临时目录；长期结论不能只依赖 `/tmp`。

### 新建自由命名材料的名称与排序

| 场景 | 格式及示例 |
|---|---|
| 主题文档、提示词组、持续分析／清单 | `<序号>_<材料类型>-<主题>.<扩展名>`；`001_用户原文-需求实现-聊天UI对齐.md` |
| 区分发生、执行或采集批次的评审／诊断／证据 | `<YYYY-MM-DD>_<当日序号>_<材料类型>-<主题>.<扩展名>`；`2026-11-03_001_评审报告-群聊气泡.md` |

类型和主题使用用户语言，直观说明用户原文、AI交接、调研分析、评审报告、诊断记录、人工检查、来源导出或失败保全等用途，不建立枚举。`_` 分隔排序前缀，`-` 分隔类型和主题；不只写编号、`final`、`latest`、`new` 或把长测试方法名当完整标题。

月份／日期补零，序号默认三位，预知规模大时从开始用四位，同目录位数一致。无日期文件按目录递增，有日期文件按同目录同日递增，取已有最大编号之后可用值，不覆盖、复用、重排或补空号。编号只表达顺序，不表达问题重要性或完成状态。协作冲突沿宿主方式处理，不设全局计数器／登记表。日期为本次报告／执行／采集的真实时间，历史来源日期另写正文；未知则无日期命名并说明。持续维护文件不随编辑改名；提示词组默认无日期，确用日期组时跨日补充仍续写原文件。

一批材料多时可用 `2026-11-03_001_群聊气泡复审/`，内部 `001_评审报告.md`、`002_覆盖分析.json`，不要每层重复日期；少量文件无需批次目录。固定机器／技能名字不改，包括 `status.json`、`design.md`、`verification.md`、`retrospective.md`、`contracts/ui-truth-index.json`、原生 `result.json`／`profile.json`、绑定预览／golden、素材哈希名及用户指定附件名。靠已有导航或可控父目录排序，不造带前缀副本。源码／测试沿宿主命名；正式文件改名需要绑定、解析器及消费者迁移，不在本约定中启动。

### 当前入口及证据保存状态

已有进度／验证／交付入口原位保留简短当前结论、适用原件、替代关系及剩余边界。新详细报告补一个指针即可，不逐图片／JSON登记，也不强制每层README／manifest。材料复杂时可在现有入口加短表。相对链接从实际引用文件解析；旧源码行号／路径和替代报告标为历史用途。人工清单解释检查方法，结果引用实际验证和用户反馈，不另维护完成状态。

恢复或交接时核对正在依赖的关键证据可读性，不每次编辑遍历所有历史链接。易清理 `build/`／临时输出说明实际位置、保留情况及宿主已有机制中的长期原件／副本。缺失时写“历史结果有记录、原件当前不可用”，说明对当前结论影响；文件缺失不代表历史验证失败或没发生。不得捏造原件、抹去失败或为补目录擅自重跑设备。

只规范新材料及正在维护的入口。旧路径、冻结哈希、STOP证据、用户文件及归档需求保留原义和只读边界，不自动搬迁、重命名、去重或删除。未来整理另列具体对象、引用影响、可逆范围及已有授权；旧名称或文件多不阻断交付。

## 用户输入完整保存

每条真实用户输入都是必要来源材料，**先完整保存原文，再提炼要求及执行动作**，包括初始指令、执行中插入的补充、纠正、选择、确认、范围变化及续接。不得按重要性／复用筛选，也不能用摘要、需求、决定或RET代替。使用唯一[用户提示词记录模板](../templates/user-prompt-record-template.md)。

先定位所属需求与任务，在该需求 `prompts/` 按独立任务一组一文件，例如 `001_用户原文-需求实现-聊天UI对齐.md`、`002_用户原文-复审验收-群聊气泡.md`。同任务初始及全部相关补充按 `输入001`、`输入002` 连续保存；输入编号与文件编号独立。换会话／日期／阶段或收到一句补充不算新任务；恢复时续写原组，真正独立任务才用下个文件编号。用户指定具体名字时遵从，不改名或复制一份规范名。

保留段落、列表、代码、链接和措辞，不改写、转义或截断。使用长于原文最长连续反引号的外层text围栏，或边界清晰的纯文本附件。时间、会话／消息ID等仅在环境真实提供时选填，不猜造也不要求平台API／hook。用户实际重复发出同文是新输入，恢复时重读同一已存消息不重复保存。原输入不能被合并摘要覆盖；有效决定由现有需求／决定记录解释并引用原文条目，被替代输入保留。

“继续”“选B”等原文照存，实际选项另标**AI上下文说明**并链接，不混入原话或扩大授权。跨需求消息在明确主归属保全一份完整原文，其他需求引用该输入，不拆句丢上下文；归属不明先核对，不能机械放入最近文件。归档后续按既有规则进入新需求并链接旧输入，不回写历史。

可访问且允许保存的附件就近保全，可用 `prompts/attachments/001_聊天UI对齐/`，从输入节相对引用；原附件名可保留。仅有易失外部路径不算保存内容。附件不可得、消息部分可见、编辑历史不可见或历史上下文丢失时，如实说明缺口，只保存真实可取得原文，不以AI重构冒充完整历史。遵守宿主敏感信息规则；必要脱敏明确标范围，不能声称字节完整。首次采用注明实际历史覆盖范围。

AI编写的可执行提示词／交接另按辅助用途归属，不混充原文；补充不散落reviews／progress／临时文件。可在既有需求入口链接提示词组，关键决定／发现引用具体输入。不新增逐消息审批、强制哈希／schema、全局输入索引、状态表、归档门禁或全量对话导出；不要求隐藏系统消息、AI推理或所有工具输出。原始输入按顺序保留与复盘统一归并是不同职责。

## Workspace

[workspace-policy.md](workspace-policy.md) 是唯一权威。默认当前 checkout；
创建或复用 worktree 必须针对当前切片明确批准准确路径
`<project-root>/.worktrees/<req-id>-<sr-id>`。任何 checkpoint 或框架默认值
都不构成同意。

## 抽象动作

| Action | 含义 | 触发 |
|--------|------|------|
| `requirement-breakdown` | kit 自有需求拆分 | `draft` |
| `ui-truth-mapping` | kit 自有受控视觉实现 | CP-UI 后的 eligible `split_ready` |
| `solution-design` | 产出并评审唯一 `design.md` | `split_ready` / `acceptance_frozen` |
| `implement` | 按当前契约执行 TDD 与评审 | 依赖就绪的 `design_ready` / `in_dev` |
| `finish` | 验证、集成并关闭切片 | 实现/验收完成 |
| `archive` | 原位收敛完成状态 | 所有适用切片 `merged` |

不得输出 `spec`、`plan`、`tasks` 动作。只有 `user_decision_required=true`
触发 CP-DESIGN，批准同时授权对应范围内的实现。

## 环境自检与选择

每次运行只读检测并在 `decisions.md` 记录所选方法：

| 框架 | 检测 | 作用 |
|------|------|------|
| spec-kit | `.specify/` 或 CLI | 可选需求/设计推理 |
| OpenSpec | `openspec/` 或 CLI | 可选棕地增量推理 |
| superpowers | skill 目录 | 设计、TDD、评审、finish 纪律 |
| ECC | 已注册命令/agent | 设计、执行与评审纪律 |
| native | 始终可用 | 完整兜底 |

`solution-design` 优先采用可用的 superpowers/ECC 设计方法；Spec Kit 和
OpenSpec 只可补充同一 `design.md` 的分析。它们不得运行会写 feature/change
目录或 spec/plan/task 文件的持久化管道。`implement` / `finish` 优先
superpowers，其次 ECC，最后 native。

## 闭环与追踪

```text
入口 guard → 框架方法 → 契约/验证 gate → 推进、重试或阻塞
```

在 `traceability.json` `source_index.design` 记录 canonical `design.md`
路径、当前 SHA-256、来源关系和推理方法。schema 2.0 不生成 `spec_refs` 或
`kind=spec|plan|tasks`；旧终态记录只读兼容。
