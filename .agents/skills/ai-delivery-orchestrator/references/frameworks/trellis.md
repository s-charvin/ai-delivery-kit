# Limited Trellis adaptation

Reuse existing guidelines and the methods of before-dev/check/update-spec/
break-loop inside the [quality loop](../delivery-quality-loop.md). Register
source paths in context.sources instead of copying their bodies. Do not run
upstream init, Task/journal, automatic commits, or default agent dispatch.

- before-dev maps to the existing requirement/design and four-entry execution
  brief; discover the actual module and state/resource owner first.
- check independently recomputes applicable rules from actual changes and checks
  original requirements, production wiring, and native results.
- update-spec maintains one explicitly writable source from stable evidence;
  imports remain read-only by default. Never lower standards to pass a check.
- break-loop preserves failures and user wording, seeks discriminating evidence,
  and follows the existing bounded retry budget.

An installed Trellis entry does not prove workflow compatibility. Diagnose
competing task authority without changing user configuration. Channel remains
optional pending an existing environment, explicit external execution need,
and verified permissions/input completeness; it is not a core dependency.

Shopify Helix's small batches, matched-state evidence, and review feedback live
in the existing stage rules. No official public Helix runtime is assumed.
Do not install same-named community reconstructions or their Stop gate.
